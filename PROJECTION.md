# Состав и границы репозитория

Основной текст находится в [report-latex/main.tex](report-latex/main.tex). Корневые [REPORT.md](REPORT.md) и [REPORT.pdf](REPORT.pdf) являются его производными. [README.md](README.md) помогает начать чтение, а [REPRODUCING.md](REPRODUCING.md) объясняет доступные проверки и условия воспроизведения. Редакция подготовлена по сохранённым результатам, без нового обучения.

Текущий PDF собирается через [report_tool.py](report_tool.py) и Tectonic; тот же скрипт генерирует Markdown из поддерживаемого подмножества LaTeX. Ссылки открывают файлы в распакованной папке рядом с REPORT.pdf. Сам PDF можно читать отдельно. Прежний [make_report.py](make_report.py) и архивный PDF сохранены.

Прежние [reports/REPORT.md](reports/REPORT.md), [reports/REPORT.pdf](reports/REPORT.pdf) и [reports/LIMITATIONS.md](reports/LIMITATIONS.md) содержат технические подробности. После аудита в двух Markdown-документах исправлены навигация и описание негативных кандидатов. Старый PDF, научные исходники и доказательные результаты сохранены без изменений. Точные исправления скопированных файлов учитываются отдельно от исторического реестра.

Отдельно распространяемый полный ZIP фиксирует предыдущую версию комплекта. Редакторское обновление репозитория не меняет и не пересобирает этот архив; новые корневые отчёты в него не добавлены. Состав Git-репозитория и состав полного ZIP различаются.

## Что зафиксировано в реестре

[projection.json](projection.json) содержит конечный перечень 526 скопированных файлов. Для каждого указаны путь, размер, SHA-256 и путь в исходной поставке. Там же перечислены все исключённые файлы с исходными размерами, хешами и причинами исключения, а также идентификаторы замороженной поставки. Эти записи относятся к сохранённым материалам и не пересчитываются под новую редакцию текста.

Файлы, созданные для репозитория, перечислены отдельно в `authored_files_not_hashed`. Это документы, LaTeX-проект, рисунки, инструменты с тестами и компактные ранги. Список точных имён совпадает с `AUTHORED` в [verify_repository.py](verify_repository.py). Произвольные файлы и шаблоны имён не разрешены. Этот реестр проверяет их наличие; хеши содержимого фиксируются отдельно при сборке и упаковке, чтобы не создавать циклическую зависимость самого реестра.

Поле `reviewed_copy_overrides` описывает исправления ограниченного списка ранее скопированных файлов: исходный SHA256 из неизменённого `copied_files`, текущие размер и SHA256, а также причину правки. Проверка принимает только заранее перечисленные пути. Первоначальные размеры, хеши и totals остаются историческими; число неизменённых копий и текущие размеры исправленных файлов выводятся отдельно. Это не перезапись истории поставки под новую редакцию.

Текущие ранги и группы пользователей находятся в [reproduction/saved-metrics64k](reproduction/saved-metrics64k). Они позволяют пересчитать метрики на 65 536 запросах и парные доверительные интервалы по пользователям. Старый [reproduction/saved-metrics](reproduction/saved-metrics) относится к 4096 запросам. Экспорты не содержат исходных ID пользователей, фильмов или историй; возможность повторной идентификации отдельно не оценивалась. Пересчёт рангов не повторяет предсказания и обучение моделей.

Числовые входы малого model replay (`fixtures`), веса и перечисленные внешние JSON с происхождением данных в Git отсутствуют. Сохранённые manifests описывают наборы, но не заменяют payloads. Сырые данные, кеши, журналы и архивы также не входят в эту проекцию. Исторические управляющие скрипты внутри `source/` сохранены как исходный код.

[.gitattributes](.gitattributes) сохраняет исходные CRLF у явно перечисленных исторических текстов и отключает текстовую нормализацию для бинарных PNG и PDF. Новые текстовые документы используют LF.

## Что проверяет код

Из корня репозитория с Python 3.12+ доступны проверки, которые используют только стандартную библиотеку и не изменяют файлы:

```text
python -B verify_repository.py
python -B source/verify_sources.py
python -B source/fullstudy/code/tools/verify_bundle.py --report-root source/fullstudy
python -B reproduction/kion_replay verify --bundle .
```

Первая команда проверяет размеры и хеши неизменённых копий и явно описанных исправлений, отсутствие файлов с признаком `omitted` и полный состав дерева: только копии из реестра и конечный список `AUTHORED`, кроме служебного `.git`. Поэтому добавление локальных fixtures или результатов сборки внутрь этого дерева приводит к отказу проверки. Содержимое `AUTHORED` по этому реестру не хешируется. Успех команды не подтверждает качество текста или вид PDF; точное соответствие Markdown исходнику проверяет `python -B report_tool.py markdown --check`.

Остальные команды проверяют сохранённые исходники, синтаксис Python и состав переносимого пакета воспроизведения. Проверка исторического набора исходников также считает метрики на маленьком вымышленном примере ранжирования. Эти команды не запускают исходные научные расчёты, численное воспроизведение моделей, обучение или загрузку данных.

Сохранённые протоколы (`receipts`) описывают успешные проверки предыдущей полной версии комплекта на исходной рабочей машине. Их наличие в репозитории не означает, что эти проверки выполнены заново, и не доказывает воспроизводимость полного обучения на чистой машине. Исторические абсолютные пути остаются сведениями о происхождении материалов; условия отдельного численного запуска описаны в [REPRODUCING.md](REPRODUCING.md).
