# KION: следующий просмотр и прогноз досмотра

Можно ли улучшить рекомендации, если оптимизировать прогноз досмотра? Каталог KION содержит фильмы и сериалы. В этой работе на данных KION сначала построена модель следующего просмотра, затем ранкер с дополнительными признаками и отдельная модель досмотра. После этого ранкер обучен с подкреплением по двум вариантам награды.

**RL ухудшил ранжирование наблюдаемых целевых просмотров.** Лучшее точечное значение MAP@10 осталось у ранкера C до RL. Отдельная проверка на 1024 запросах показала рост предсказанного досмотра у обоих вариантов RL, более сильный у completion. Это изменение выбора по оценке фиксированной модели, а не улучшение точности её прогноза или измеренный рост реального досмотра.

## Как устроен эксперимент

1. **GPT по истории просмотров.** Модель получает последовательность ID фильмов и оценивает следующий фильм. Она также использует признаки каталога, тексты, сведения об участниках и пользователе, но не генерирует текст рекомендаций.
2. **Смешанный список кандидатов.** Для каждого запроса собраны 1024 фильма: предложения GPT, популярные за последнюю неделю фильмы и фильмы, похожие по совместным просмотрам. Реальный следующий просмотр специально в список не добавляется.
3. **Ранкер.** Небольшая обучаемая «голова» меняет порядок кандидатов. Вариант A уже использует представления истории и кандидата из GPT, оценку GPT и недельную популярность. B добавляет статистику, C добавляет признаки соответствия кандидата истории пользователя. Веса самого GPT на этой стадии не меняются.
4. **Модель досмотра (RM).** Отдельная модель по демографии и истории пользователя, признакам фильма и его ID предсказывает долю досмотра. Это прогноз, а не измеренный результат будущего показа.
5. **Обучение с подкреплением (RL).** Обучается копия головы C; исходная остаётся неизменным эталоном. Первый вариант награды, completion, использует прогноз досмотра. Второй, residual, вычитает из него сглаженный средний досмотр фильма. Отклонение от исходного ранкера ограничивается; в итоговой проверке оно сопоставимо у двух вариантов.

GPT обучался две эпохи на примерно 3,5 млн подготовленных примеров. Каждый ранкер A/B/C обучался три эпохи на 262 144 примерах. Это разный объём обучения, а не три новых прохода по всему набору GPT.

## Что получилось

В текущей оценке на 65 536 запросах от 53 024 пользователей C сохранил лучшее точечное значение MAP@10: **0,094978**. Метрика учитывает позицию наблюдаемого целевого просмотра среди первых десяти рекомендаций. Запросов больше, чем пользователей: в первый активный день оценочной недели у пользователя могло быть несколько просмотров, порядок внутри дня неизвестен.

Оба варианта RL уступили C. При равном усреднении трёх фиксированных запусков потеря MAP@10 составила 0,002921 для completion и 0,001350 для residual. Residual потерял меньше: разность residual минус completion равна **+0,001572**, 95% интервал **[+0,000879; +0,002237]**. Интервал получен повторной выборкой групп пользователей и относится к этим моделям и этой выборке; поправка на множественные сравнения не применялась.

Оценочная выборка уже использовалась при разработке; её расширение не стало независимым тестом. Нового обучения не было. Награда RM проверена отдельно на 1024 запросах, а не на всех 65 536. Отдельного сравнения с ранжированием только по популярности нет. Эти результаты не устанавливают рост реального досмотра, удовлетворённости или возврата пользователей.

Пять последовательных рекомендаций проверены на 256 историях. При выборе самого вероятного фильма residual давал меньше повторов и меньшую концентрацию выдачи, чем completion. При случайном выборе по вероятностям различие не подтвердилось. Это диагностика генерации без реальных откликов пользователей. Отдельная проверка длительности не подтвердила смещение completion к коротким фильмам; неполные метаданные не позволяют считать эту гипотезу опровергнутой.

Быстрая проверка клона из его корня, Python 3.12+, только стандартная библиотека:

```text
python -B verify_repository.py
python -B source/verify_sources.py
python -B source/fullstudy/code/tools/verify_bundle.py --report-root source/fullstudy
python -B reproduction/kion_replay verify --bundle .

```

Текущую таблицу на 65 536 запросах и интервалы можно пересчитать по сохранённым рангам и обезличенным группам пользователей. Для этого нужен NumPy 2.5.4:

```text
python -B reproduction/saved_metrics64k.py verify --data reproduction/saved-metrics64k
python -B reproduction/saved_metrics64k.py recompute --data reproduction/saved-metrics64k
python -B reproduction/saved_metrics64k.py bootstrap --data reproduction/saved-metrics64k
```

`bootstrap` повторяет расчёт 2000 выборок групп пользователей; это более долгая проверка. Команды не повторяют обучение и предсказания моделей. Старый скрипт `reproduction/saved_metrics.py` и каталог `reproduction/saved-metrics` относятся к историческим 4096 запросам. Веса и входы малого model replay передаются отдельно; условия получения и проверки описаны в [REPRODUCING.md](REPRODUCING.md). Полное обучение из исходных данных на другой машине пока не воспроизведено.

Проверка ссылок работает без сети: проверяет локальные файлы, Markdown-якоря и ссылки на файлы ожидаемой ветки. Она не подтверждает доступ внешнего читателя к закрытому репозиторию. Для локальных ссылок из PDF сохраняйте рядом всю папку репозитория или распакованный комплект. Сам PDF можно читать отдельно; открытие локальных ссылок зависит от просмотрщика.

## Читать и собирать отчёт

Основной текст редактируется в [report-latex/main.tex](report-latex/main.tex). Корневой `REPORT.md` генерируется из него:

```text
python -B report_tool.py markdown
python -B report_tool.py markdown --check
```

Для PDF нужен [Tectonic](https://github.com/tectonic-typesetting/tectonic/releases/tag/tectonic%400.17.0); здесь использована версия 0.17.0. Из корня клона в PowerShell замените путь к своему компилятору. Каталог сборки и выходной PDF должны отсутствовать; кеш можно использовать повторно. Все пути сборки передаются как абсолютные:

```powershell
$ReportParent = (Resolve-Path -LiteralPath '..').Path
$BuildDir = Join-Path $ReportParent 'kion-report-build'
$Pdf = Join-Path $ReportParent 'kion-report.pdf'
$Cache = Join-Path $ReportParent 'tectonic-cache'
New-Item -ItemType Directory -Force -Path $Cache | Out-Null
python -B report_tool.py build --tectonic C:/tools/tectonic.exe --cache-dir $Cache --work-dir $BuildDir --output $Pdf --allow-resource-downloads
```

Первый запуск явно разрешает загрузку ресурсов TeX в указанный кеш. При повторной сборке задайте новые `--work-dir` и `--output` и уберите `--allow-resource-downloads`: тогда используется только кеш. Скрипт сохраняет рядом со сборкой команду, хеши входов, логи и результат компилятора. Сборка не проверяет качество вёрстки автоматически. Для чтения готового [REPORT.pdf](REPORT.pdf) компилятор не требуется.

Прежние `make_report.py` и `reports/REPORT.pdf` сохранены для истории. Текущая версия собирается из LaTeX через `report_tool.py`.
