# One fixed residual H1 fit from original C

`residual.py` imports only the standard library. It exposes `train(request, check=None)` / `run(request, check=None)`, root-only `probe(request, check=None)`, and `load_head(request, torch, device, checkpoint)` for explicitly named residual arms.

The new preregistration contract `kion-C-residual-RL-preregistered-v1` is separate from old RM/frontier preregistration. It requires residual formula/coefficient1, beta0.5, temperature1, original-C initialization, known old results, one additional fit, no GPT unfreeze/RM fit/SFT, sampler_seed20261024, checkpoints0/250/500/1000, and optimizer `{name:Adam, updates:1000, batch_size:16, lr:1e-5, grad_clip:1, weight_decay:0, alpha_ce:0}`. Primary comparison is fixed latest1000; no frontier, selection or metric-based stopping is called.

The numerical seam directly invokes the exact source-pinned old `policy_v2` functions: `producer_layout`, `prepare_shaped_inputs`, `score_shaped`, `precision`, `rank`, `distribution`, `effective_advantage`, and `exact_loss`. No function globals are replaced. Thus partial producer batch sizes/slots, duplicate sampling occurrences, candidate chunks64, and one loss mean over logical real B16 are retained. Unsupported actions have neutral advantage but stay in the1024-way softmax and KL. No targets enter the objective. The old eligibility order and `random.Random(20261024).choice` sequence are retained; the actual sequence digest is recorded.

The trainer requires both-cohort `prefit.json` with a nondegenerate prior and exact utility/preregistration bindings, plus a pinned successful original all512 CUDA FP16 parity/backward receipt. `probe` explicitly calls the unchanged old `repair_probe` into a new owned path and creates no optimizer. The old receipt is reusable only if its implementation/cache/C hashes match exactly. Trainer rechecks all512 update0 scores against cached original C with atol0.003/rtol0.001, exact top10 and exact actor/reference equality before creating Adam. Every actual update checks finite loss/gradients/parameters, clip1; the first actual gradient must be nonzero. Frozen reference identity and nonzero finite parameter delta are required at completion.

Training request combines the original pinned-head loading fields (`head_dir`, source hashes for `heads.py` and its dependencies), `policy_module`, `utility_module` (must be this root's `reward/utility.py`), `source_hashes` including both new and frozen helper modules, `preregistration`/`preregistration_sha256`, `deadline_utc`, `device:cuda`, `precision:cuda-fp16`, `amp_validation_passed:true`, original train `cache_dir`/`reward_dir`, `utility_dir:NEW/reward/residual-r1/train`, `prefit_path:NEW/reward/residual-r1/prefit.json`/`prefit_sha256`, `parity_proof:{path,sha256}`, and `rl_output:NEW/policy/residual-r1`.

Both module fields accept a path string or `{path,sha256}` descriptor; descriptor pins are checked as well as the required source_hashes map. This supports the common evaluator/rollout request shape.

The fixed fresh output path permits one fit namespace; failed attempts are retained and cannot resume or reroll through this adapter. Native control remains responsible for admission, singleton heavy-job ownership, deadline/resource enforcement, exact request/input/source pins and the campaign's one-fit ceiling.

Checkpoints use separate contract `kion-current-C1070-residual-H1-v1` and the same strict C state_dict shape. `load_head` accepts `residual_checkpoint_sha256`, falling back to `rl_checkpoint_sha256`, and verifies residual utility semantics and original-C ancestor. It never relabels the residual checkpoint as old `selected`. `training.json` records `state:completed`, updates1000, actual_optimizer_updates1000, checkpoints step/path/SHA, original-C/cache/utility/reward/prereg/prefit/probe pins, beta, sampler digest, delta, frozen reference and zero supervised updates. Incomplete runs have no completed receipt and must not be reported as1000.

Stdlib synthetic/source tests verify contracts, sampler sequence, deferred imports and explicit seams. They do not prove numerical parity, native runtime viability or a trained result. Real arrays/models/GPU/provider jobs were not opened during authoring.
