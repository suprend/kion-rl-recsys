# Передача внешних входов

`transfer_inputs.py` готовит конечный список файлов и по отдельной команде копирует
его в новый внешний каталог. Обычный запуск читает только небольшой JSON входа и
проверяет размеры через файловую систему. Он не хеширует payload, не запускает ML,
не ищет секреты, не отправляет файлы и не обходит каталоги рекурсивно.

Проверка перечисленных файлов не доказывает полноту входов эксперимента.
`closure_complete` всегда остаётся `false`. Перенос исторических подготовленных
входов не является пересборкой из сырых данных.

## Явный формат

JSON должен иметь ровно следующие поля. `entries` содержит от 1 до 4096 файлов.
Для каждого файла нужны абсолютные `logical` и `physical`, SHA-256 и точный размер.
`logical` сохраняет исходную идентичность. `physical` указывает существующий файл
на текущей машине. `destination` задаёт относительный путь внутри `inputs/`.

```json
{
  "contract": "kion-external-file-transfer-v1",
  "schema_version": 1,
  "entries": [
    {
      "logical": "D:/original/data.bin",
      "physical": "/absolute/local/data.bin",
      "destination": "inputs/D/original/data.bin",
      "sha256": "<64 lowercase hexadecimal characters>",
      "bytes": 123
    }
  ]
}
```

Пример показывает схему, значения заменяются фактическими. Ссылки, junction,
reparse points, hard links, дубли идентичностей, совпадающие назначения,
`..`, специальные имена Windows и альтернативные потоки запрещены.

Поддержаны два явных преобразования:

* `--format gpt-report` читает `transfer_recipe` отчёта `gpt_inputs.py`
  или `gpt_transitive.py`.
  Дополнительно нужен `--bindings bindings.json`, точное отображение каждой
  исходной идентичности в локальный файл. Размер получается через stat.
  Назначения берутся из recipe. Они могут разносить соседние файлы по разным
  каталогам, поэтому GPT-потребителю нужен точный resolver bindings.
* `--format rl-report` читает `bindings` отчёта `train_rl.py` с контрактом
  `kion-historical-cache-rl-preparation-v1`. Размеры и SHA берутся из bindings.
  Назначение сохраняет дерево исходного пути под `inputs/<drive>/`, чтобы
  относительные ссылки cache и reward продолжали работать.

Другие форматы и автоматическое угадывание структуры не поддерживаются.
RL bindings не перечисляют автоматически весь репозиторий, `source_pins`,
`beta_evidence` и все входы остальных стадий. Добавляйте недостающие файлы только
явными записями стандартного manifest с подтверждёнными SHA и размерами.

## План и копирование

Команды выполняются из корня проекта в подготовленном Python-окружении.
Все пути ниже являются заполнителями. Каталог родителя результата уже должен
существовать. Результат должен находиться вне checkout.

```text
python -B reproduction/transfer_inputs.py --input /absolute/manifest.json
python -B reproduction/transfer_inputs.py --input /absolute/gpt-report.json --format gpt-report --bindings /absolute/bindings.json --report /absolute/new-plan.json
python -B reproduction/transfer_inputs.py --input /absolute/rl-report.json --format rl-report --copy-inputs --destination /absolute/new-bundle
```

Без `--copy-inputs` команда выводит план в stdout и ничего не создаёт, кроме
явно указанного нового `--report`. В плане `manifest` содержит стандартную форму
списка. Для её повторной подачи извлеките объект `manifest` в отдельный JSON.
Успешный план означает только корректность списка и совпадение размеров.

Копирование разрешается только сочетанием `--copy-inputs --destination`.
Каждый файл читается блоками, его SHA-256 и размер сравниваются с ожидаемыми,
записанная копия повторно проверяется. Исходные файлы открываются только на чтение.
Изменение размера, идентичности или времени изменения во время копирования
прерывает операцию. Во время работы не меняйте исходные файлы, каталог результата
и их родителей: инструмент не является защитой от конкурентной подмены файловой
системы привилегированным процессом.

## Получатель и признаки завершения

Если окончательное расположение пакета отличается от `--destination`, задайте
`--receiver-root /absolute/final-bundle` в команде копирования. Допустим также
канонический Windows-путь с `/`. Этот параметр задаёт только будущие пути в
bindings, не создаёт и не читает удалённый каталог. Перенесите весь пакет именно
в это расположение. Без параметра bindings указывают на `--destination`.

Успешный пакет содержит:

* `inputs/` с проверенными копиями;
* `bindings.json`, отображение исходной идентичности в путь получателя;
* `manifest.json` и `recipe.json`, одинаковые конечные списки с размерами и SHA;
* `started.json` и финальный `completed.json`.

`completed.json` появляется последним, через переименование полностью записанного
временного JSON. Получатель должен проверить `state == "completed"` и повторно
проверить SHA после доставки. Для этого можно запустить это же явное копирование
из `manifest.json` в ещё один новый внешний каталог. Обычный запуск на manifest
проверяет только размеры. Перенос по сети и упаковка в архив выполняются отдельно.

При ошибке остаются частичные файлы и `failed.json`, если файловая система
позволяет его записать. Завершение процесса извне может оставить только
`started.json`. Ни один такой каталог не считается готовым; повторный запуск
требует нового каталога. Автоматического удаления и перезаписи нет.

Проверки используют маленькие временные файлы. Реальные payload не копировались,
их контрольные суммы этим изменением не проверялись.
