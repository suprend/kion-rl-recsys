# Обучение r1 и калибровка r2

`train_reward_model.py` связывает две сохранённые процедуры: r1 обучает
модель награды, r2 уточняет её калибровку, сохраняя обученные деревья.
По умолчанию скрипт только показывает план. Он проверяет исходники и JSON,
наличие и размеры файлов данных. Массивы не читает, NumPy/CatBoost не
импортирует, дочерние процессы не запускает. Хеши данных в плане остаются
ожидаемыми, а не проверенными.

Для описаний набора RM и модели разрешён JSON до 64 МиБ: историческое
описание занимает 26 882 770 байт из-за сведений о происхождении признаков.
Для исходников и остальных JSON прежний предел 4 МиБ сохраняется.

Команды для просмотра будущего запуска:

```text
<python> -B reproduction/train_reward_model.py fit-r1 --bundle <rm-data> --output <fresh-r1> --python <rm-python>
<python> -B reproduction/train_reward_model.py repair-r2 --bundle <same-rm-data> --old-artifact <fresh-r1> --output <fresh-r2> --python <rm-python>
```

Для выполнения нужен отдельный флаг: `--execute-training` для обучения или
`--execute-repair` для калибровки. Оба этапа вычисляют предсказания. Калибровка
использует только строки с поддержанными обучением объектами и сохраняет
прежний ответ для остальных. Оба флага одновременно запрещены.
`--timeout-seconds` ограничивает каждый дочерний процесс; по умолчанию 3600.
**В этой поставке обучение и калибровка не запускались.**

Оригинальные параметры закреплены хешами исходников:

- Две модели: с историей и без неё; глубина 4, до 160 деревьев.
- `seed=2026`, CPU, 2 потока, `learning_rate=0.05`, `l2_leaf_reg=10`.
- `border_count=64`, `loss_function=RMSE`, `od_wait=30`, `use_best_model=True`.
- Строки: 100000 для обучения, 20000 для выбора модели, 20000 для калибровки.
- Окружение: Python 3.12.14, NumPy 2.5.4, CatBoost 1.2.10, SciPy 1.18.1.

Модель выбирает исходный код по выборке `select`; исторический победитель
`history_depth4` не задаётся заранее. Перед выполнением проверяются версии
окружения. Подробности: [ENVIRONMENTS.md](ENVIRONMENTS.md).

Входные данные готовит [prepare_reward_data.py](PREPARE_REWARD_DATA.md):
`manifest.json`, 33 файла NPY с полями строк, `catalog.npz`, шесть файлов
`x`/`lengths` и `full_target_support.npz`. Проверяются размеры выборок,
словарь объектов, разделение по датам, правила построения признаков и
отсутствие выдуманных нулевых оценок. Проверяются также закреплённые хеши
CSV, метаданных и всех исходников подготовки признаков. Перед выполнением
и после него скрипт пересчитывает хеши всех перечисленных файлов данных.

Новый набор данных может иметь новые хеши. Скрипт сохраняет их, не подменяя
историческими. Само совпадение файлов с их описанием ещё не доказывает,
что пересобранные признаки численно совпадают с историческими.

По умолчанию используется `--lineage newly-fitted`: r2 получает настоящую
подпись новой модели r1 через `--expected-old-signature`. Она проверяется
вместе с исходником r1 и привязкой `report.bundle_manifest_sha256`.
Поэтому калибровка требует тот же неизменённый набор данных, на котором
обучалась модель. Код r2 дополнительно проверяет схему признаков и число
обучающих примеров по объектам.

Режим `--lineage historical-artifact` предназначен только для калибровки
сохранённой исторической модели. Он требует полные закреплённые подпись r1
(`4b7c87e5…`) и хеш описания данных (`42d7532a…`). Новое обучение создаёт
отдельный результат; его совпадение с исторической моделью нужно проверять.

Результат записывается в новый каталог: `manifest.json`, `scorer.npz`,
`model.cbm`. Проверяются подпись, исходники, привязка к данным, конфигурация
и хеши файлов. После калибровки также проверяются подпись исходной модели
и побайтовая сохранность `model.cbm`. План и итог записываются рядом в
`<output>.rm-launch.json`.

Существующие выходные каталоги, пересечения с входами и исходниками,
символические ссылки и junction запрещены. Изменение исходников или данных
прерывает выполнение. При ошибке, истечении времени или отмене после запуска
журнал получает статус `failed-or-cancelled`; частичные результаты сохраняются.
Нулевой код возврата без проверенных файлов не считается успехом.

Десять тестов подменяют дочерний процесс и используют искусственные данные.
Они проверяют команды, разрешающие флаги, новую подпись, ошибки, отмену,
ограничение времени и обнаружение изменённых файлов. Реальное окружение,
обучение, предсказания, калибровка и совпадение исторических метрик этими
тестами не проверены.
