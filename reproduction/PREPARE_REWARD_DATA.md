# Подготовка входов RM

`prepare_reward_data.py` добавляет два отдельных шага: `basic-features` и
`reward-data`. По умолчанию он только печатает план. Используются исходники
`bundle-rm-r1` (11 Python-файлов); отсутствующий в сохранённом наборе конфиг лежит
отдельно в `reproduction/profiles/kion-series-v1.json` с историческим SHA256.
Проверяются SHA256 этих файлов и небольших JSON; CSV/NPZ только проверяются на
наличие и размер. `expected_sha256` для массива не означает проверку содержимого.
План не импортирует NumPy и не запускает процессы, даже для проверки окружения.

Примеры из корня клона. Каталоги выходов должны отсутствовать, а родительские
каталоги должны существовать. Укажите собственные пути, данные и отдельный RM Python:

```text
python -B reproduction/prepare_reward_data.py basic-features --raw ../kion-raw --prepared ../kion-prepared --output ../kion-basic-new --python ../kion-env-rm/Scripts/python.exe --input-mode rebuild
python -B reproduction/prepare_reward_data.py reward-data --raw ../kion-raw --prepared ../kion-prepared --basic ../kion-basic-new --output ../kion-rm-data-new --python ../kion-env-rm/Scripts/python.exe --input-mode rebuild
```

На Linux/macOS интерпретатор среды расположен в `../kion-env-rm/bin/python`.
Каждую стадию нужно запускать отдельно. Второй план требует уже существующий
basic-пакет. Он не создаёт его автоматически.

Для будущей явно разрешённой подготовки к соответствующей команде добавляют
`--execute-prepare --timeout-seconds 3600`. Это уже чтение полных файлов данных
и вычисление признаков. Драйвер проверяет Python 3.12.14, NumPy 2.5.4,
CatBoost 1.2.10 и SciPy 1.18.1, затем вызывает неизменённый CLI. Данные RM имеют
фиксированные размеры выборок 100000/20000/20000 и пакета 512; уменьшение через этот
драйвер не предусмотрено. Проверка окружения читает версии пакетов, не обучает
и не загружает модель. Среда actor с NumPy 2.2.6 сюда не подходит.

Есть два явных режима входов:

- `historical` (по умолчанию) требует исторические байты metadata и
  train/val при basic-подготовке. Исходные CSV проверяются по историческим SHA256.
  Reward-подготовка принимает basic-контейнер с проверяемой связью с этими входами.
- `rebuild` принимает новые train/val NPZ после `prepare_data.py`. Обязателен его
  `prepare-launch.json` с завершённым запуском, закреплённым производителем,
  проверенными исходными входами, параметрами и совпадающими путями. При исполнении
  закреплённые `kion_sex_features.read_metadata` и `kion_local_features.read_split`
  проверяют метаданные и ключи строк: число строк, пользователей и
  исторические SHA256 упорядоченных user_id/target_item_id/target_date.
  В плане эта проверка ещё не выполнена. Детерминированный metadata.json
  не содержит времени/выходного пути, поэтому для него сохраняется исторический
  SHA256 и точная схема, словарь, контекст и seed. Новые NPZ получают отдельные
  фактически вычисленные хеши; исторические хеши не подменяются.

Basic-манифест должен связывать действительные входы и сохранять исторические
197 координат item_features. В RM-манифесте проверяются разбиение, дата отсечения,
словарь, динамические признаки кандидатов, размеры выборок, 33 файла строк,
catalog, шесть файлов истории и full_target_support. После исполнения проверяются хеши
выходных файлов и повторно входы/исходники. Путь metadata передаётся явно;
исторические JSON и их старые пути происхождения не переписываются.

Протокол `<output>.prepare-launch.json` создаётся рядом с выходом, чтобы не
нарушать требование исходного CLI о новом каталоге. При ошибке, тайм-ауте или
отмене он фиксирует `failed-or-cancelled`; частичные данные сохраняются.
Успешный код возврата без манифеста/файлов не считается готовым результатом.
Выходы должны быть вне кода и входов; symlink/junction в путях данных отвергаются.
При явном исполнении создаётся отдельный свежий `<output>.prepare-runtime`:
11 точных исходников в `scripts/`, конфиг в `configs/datasets/` и точные копии
потребляемых CSV и имеющегося raw-манифеста в `raw/`. Копирование требует места
на диске. CLI получает этот путь: dynamic ищет series-конфиг у предков raw,
а static ищет его относительно исходника. Оба находят закреплённый файл.
План показывает оба raw-пути и команду в рабочем каталоге, но не создаёт его.
Хеши проверяются до и после процесса; каталог сохраняется рядом с протоколом.

Это контракт подготовки, а не доказательство воспроизведения модели. Новые
контейнеры и манифесты могут отличаться из-за путей и времени. Проверка трёх
ключей строк покрывает вход basic/RM, но не доказывает равенство всех x/history
массивов prepared или GPT. Протокол содержит локальную запись запуска без цифровой
подписи. Полная численная эквивалентность, установка среды с нуля, обучение
RM-r1 и исправление калибровки RM-r2 остаются отдельными непроведёнными проверками.
В этих командах нет обучения, предсказаний моделей, калибровки или этапов actor.

Проверка контракта без научных библиотек:

```text
python -B -m unittest discover -s reproduction -p test_prepare_reward_data.py -v
```

Тесты используют маленькие временные файлы, реальные AST функций argparse и
подставные процессы. Они проверяют вызов исходного кода и запреты, не создают научные данные.
