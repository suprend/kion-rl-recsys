# Входные файлы GPT

`gpt_inputs.py` проверяет наличие входных файлов и составляет список для переноса. Он проверяет SHA256 исходных метаданных и небольших файлов кода; для массивов и весов проверяет только наличие и размер. Обучение и инференс не запускаются.

Профиль `profiles/gpt-inputs.json` содержит 1 929 ссылок из исходного манифеста провайдера native-r6 и манифеста восстановления partial-E2. После удаления повторов список переноса содержит 274 файла. Сами данные и веса в профиль не включены.

## Запуск

Создайте UTF-8 файл `../kion-gpt-bindings.json` с содержимым `{}` вне клона репозитория. Отчёты также сохраняйте вне клона. Выполните из корня репозитория:

```powershell
python -B reproduction/gpt_inputs.py --bindings ../kion-gpt-bindings.json --output ../kion-gpt-inputs.json
```

В `../kion-gpt-inputs.json` появятся отсутствующие привязки и `transfer_recipe`: исходное имя каждого файла, ожидаемый SHA256 и предложенное место в пакете переноса. Инструмент не копирует файлы.

Получив файлы, заполните `../kion-gpt-bindings.json`. Ключи берите **точно** из поля `logical` профиля или отчёта; значения замените абсолютными путями к своим копиям. Исходное логическое имя — идентификатор происхождения, а не путь, который должен существовать на вашей машине. Для каждого файла нужна отдельная привязка; привязка каталога её не заменяет. Автоматического обращения к старым путям нет. Исходные манифесты сохраняйте без изменений.

Повторите проверку с новым именем отчёта:

```powershell
python -B reproduction/gpt_inputs.py --bindings ../kion-gpt-bindings.json --output ../kion-gpt-inputs-bound.json
```

Выходной файл должен быть новым. Код завершения `1` означает, что отчёт создан, но готовность к запуску GPT не подтверждена. Код `2` означает ошибку проверки.

## Статусы

| Статус | Значение |
|---|---|
| `verified_metadata`, `verified_source` | SHA256 метаданных или кода совпал |
| `present_unverified_payload` | Файл данных или весов существует; содержимое не проверено |
| `blocked_binding` | Не задан локальный путь |
| `blocked_metadata` | Нет исходного манифеста для проверки ссылки |
| `blocked_missing` | По указанному пути файла нет |
| `blocked_source_hash` | SHA256 кода не совпал |

## Вложенные входы

Отдельная команда проверяет десять дочерних документов: базовые и текстовые
признаки, индексы событий, диагностику и assessment провайдера. Последний
сверяется по SHA256 байтов и каноническому хешу из родительского манифеста;
он добавляет ссылки на evidence/review компонентов. Общий список переноса
содержит 370 файлов.

```powershell
python -B reproduction/gpt_transitive.py --bindings ../kion-gpt-bindings.json --output ../kion-gpt-transitive.json
```

Недостающие привязки будут указаны в отчёте. Добавляйте их в тот же словарь
по исходным именам. Массивы и веса эта команда не читает. Для копирования
проверенного списка предусмотрена [команда переноса](TRANSFER_INPUTS.md).

## Что ещё требуется

Проверка охватывает прямые ссылки провайдера, перечисленные дочерние манифесты
и семь файлов восстановления partial-E2 вместе с указанными свидетельствами
их происхождения. Содержимое весов, состояние оптимизатора, позиция восстановления
и условия H5 не проверяются.

Загрузчик `gpt_complete.py` и адаптер [train_gpt.py](train_gpt.py) уже соединены с исходным обучением. [GPT_TRAINING.md](GPT_TRAINING.md) описывает создание запроса из транзитивного inventory, bindings и ожидаемого config, проверку без обучения и отдельный флаг выполнения нового непрерывного запуска до E2. Это не восстановление исторического partial-E2.

Статический аудит активных веток загрузчика сопоставил 334 логических имени и хеша с этим списком и 41 встроенным runtime-исходником без пропусков и конфликтов. Локальная проверка inventory читала только 56 разрешённых файлов метаданных и кода; содержимое массивов и весов не проверялось. Это подтверждает конечный перечень потребляемых файлов, а не успешную загрузку provider или обучение.

Компоненты загрузчика и обучающий адаптер проверены на искусственных данных; полный provider/CUDA запуск не выполнялся. Отдельный `execute_head_bank.py` с `head_bank_hooks.py` уже реализует исполнение банка от закреплённого исторического E2, но требует собственных query-store, старого банка и графов. Эти зависимости не становятся готовыми от наличия GPT inventory; новый E2 не подставляется вместо исторического автоматически.

Поэтому `ready`, `closure_complete` и `payloads_hashed` остаются `false`, даже если все 370 файлов найдены. Сквозной путь исходные CSV → все результаты пока не закрыт. Одних исходных CSV недостаточно для восстановления исторических внешних данных и принятых экспертных решений.

```powershell
python -B -m unittest discover -s reproduction -p test_gpt_inputs.py
python -B -m unittest discover -s reproduction -p test_gpt_transitive.py
python -B -m unittest discover -s reproduction -p test_train_gpt.py
```
