# План подготовки банка кандидатов

[prepare_head_bank.py](prepare_head_bank.py) проверяет небольшие метаданные и
наличие явно указанных файлов, затем печатает JSON-план. **Эта команда не
запускает подготовку банка:** `ready` всегда равен `false`, а `--execute-preparation`
завершается ошибкой до загрузки модели и создания выходной папки.

Из корня репозитория, Python 3.11+:

```powershell
python -B reproduction/prepare_head_bank.py --output-dir C:/kion-output/new-bank
python -B reproduction/prepare_head_bank.py --bindings C:/inputs/bank-bindings.json --output-dir C:/kion-output/new-bank
python -B -m unittest discover -s reproduction -p test_prepare_head_bank.py
```

Код возврата 0 означает, что план построен, а не что данные готовы. Выходная
папка должна быть новой и находиться вне входных данных и исходников.

Файл `--bindings` сопоставляет точные исходные пути с локальными абсолютными
путями. Например, для старого банка нужны отдельные привязки папки и манифеста:

```json
{
  "D:/tlab-recsys-2026/artifacts/task2-kion/three-head-pilot-20261024-r1/cache/train": "C:/inputs/old-bank",
  "D:/tlab-recsys-2026/artifacts/task2-kion/three-head-pilot-20261024-r1/cache/train/bank.json": "C:/inputs/old-bank/bank.json"
}
```

Без привязки зависимость получает статус `blocked_input`. Программа не ищет её
на исторических дисках автора. Символические ссылки, junction и неоднозначные
привязки отклоняются. Исходная конфигурация сохранена без изменений в
[head-bank-request-r1.json](profiles/head-bank-request-r1.json); её контрольная
сумма закреплена в программе. Старые сроки запуска служат только происхождением
конфигурации и не разрешают новый запуск.

Рецепт сохраняет все 32 768 строк старого банка и расширяет его до 262 144 строк
с seed 20261024 и исходными квотами по датам. В каждой строке 32 кандидата:
положительный первым и 31 различный отрицательный. Все положительные объекты
того же пользователя на ту же дату исключаются из отрицательных. Старые строки
и таблица объектов должны переноситься без пересчёта.

План не читает содержимое массивов и не подтверждает их целостность.
`unresolved_execution_seams` описывает ограничения самого планировщика.
Обучение, инференс, загрузка данных из сети и построение графов этой командой
не выполняются.

## Явный запуск исторического банка

[execute_head_bank.py](execute_head_bank.py) предоставляет исполняемый адаптер
исходного построителя банка. Это расширенный API для воспроизведения с готовыми
историческими входами, **не полный запуск из сырых CSV одной командой**.
Файл `spec` создаёт отдельный режим `--build-spec`. Он объединяет закреплённые
профили GPT и исторический запрос, автоматически находит сохранённые исходники
в клоне и добавляет имена/суммы массивов из небольших метаданных старого банка,
графов и квитанции хранилища запросов. Массивы и модели он не читает.

```powershell
python -B reproduction/execute_head_bank.py --build-spec --input-root C:/kion-inputs --reuse-root C:/kion-inputs/old-bank --graph-root C:/kion-inputs/graphs --output-dir C:/kion-output/fresh-bank-run --max-seconds 10800 --spec-output C:/bank-spec.json
```

`--input-root` — родитель путей `inputs/<hash>/<filename>` из `transfer_recipe`
инвентаризации GPT. При другой раскладке можно добавить `--bindings C:/bindings.json`:
это словарь точных исторических путей в локальные файлы, совместимый с GPT
inventory; суммы переписывать вручную не нужно. Старый банк и графы задаются
корнями пакетов с исходными именами файлов. Сами файлы builder не переносит.

Builder записывает новый `spec` и печатает инвентарь с отсутствующими файлами и
`metadata_prerequisites` — точными локальными адресами ещё нужных метаданных.
Пока нет старого `bank.json`, квитанции полного query-store или sidecar `latest.json`,
список соответствующих дочерних файлов неполон. После их предоставления повторите
builder с новым `--spec-output`: он перечислит необходимые графы по квотам дат
и добавит их массивы после чтения дескрипторов. `ready=false` сохраняется, потому
что целостность больших payload проверяется только при явном выполнении.

Формат записанного `spec.bindings` отличается от входного словаря builder и
словаря для `prepare_head_bank.py` выше.

Готовый полный перечень для владельца исторических входов —
[head-bank-transfer.json](profiles/head-bank-transfer.json): 1098 внешних файлов,
66 160 518 125 байт (66,16 GB). Ещё 112 исходников берутся из клона. Данные и
веса в Git не включены. `physical` в этом рецепте — пути на машине владельца,
включая подготовленные обычные копии четырёх бывших hardlink-файлов; на другой
машине их нужно явно перепривязать к имеющимся файлам. Имена, суммы, размеры и
`destination` менять для этого не требуется.

Передача выполняется отдельно: сначала read-only проверка, затем только по
явному разрешению копирование с проверкой SHA. Следующий пример предполагает,
что получатель разместит переданный пакет в `C:/kion-bank-inputs`:

```powershell
# На машине владельца: только metadata/stat-проверка полного рецепта.
python -B reproduction/transfer_inputs.py --input reproduction/profiles/head-bank-transfer.json --format manifest
# На машине владельца: явное копирование; destination должен быть новым.
python -B reproduction/transfer_inputs.py --input reproduction/profiles/head-bank-transfer.json --format manifest --copy-inputs --destination D:/bank-transfer-r1 --receiver-root C:/kion-bank-inputs
# На машине получателя, после размещения пакета в C:/kion-bank-inputs:
python -B reproduction/execute_head_bank.py --build-spec --bindings C:/kion-bank-inputs/bindings.json --input-root C:/kion-bank-inputs --reuse-root C:/kion-bank-inputs/inputs/D/tlab-recsys-2026/artifacts/task2-kion/three-head-pilot-20261024-r1/cache/train --graph-root C:/kion-bank-inputs/inputs/E/codex-kion-full-joint-e1-20261024-r1/cache --output-dir C:/kion-output/fresh-bank-run --max-seconds 10800 --spec-output C:/bank-spec.json
```

`transfer_inputs.py` сам создаёт `bindings.json`: точный `logical` каждого файла
сопоставляется с `receiver-root/destination`. Эта раскладка сохраняет соседство
массивов старого банка и графов. Поэтому получателю не требуется вручную
перечислять сотни привязок или восстанавливать их происхождение. Успешный перенос
всех 66,16 GB и настоящий инференс в рамках разработки адаптера не выполнялись.

```powershell
# По умолчанию — только план, без загрузки модели и чтения массивов.
python -B reproduction/execute_head_bank.py --spec C:/bank-spec.json
# Отдельный явный запуск: создаёт банк и выполняет инференс принятого E2.
python -B reproduction/execute_head_bank.py --spec C:/bank-spec.json --execute-bank
```

Все поля `spec` обязательны. Ниже показана структура; для получения заполненного
файла используйте builder выше. Пустой список `bindings` не разрешает выполнение.

```json
{
  "mode": "historical-E2-nested32768-to262144-v1",
  "bindings": [],
  "output": "C:/kion-output/fresh-bank-run",
  "reuse_root": "C:/inputs/old-bank",
  "graph_root": "C:/inputs/existing-graphs",
  "max_seconds": 10800,
  "manifest_sha256": "a8e6e78334c1ba1ca5519a09785f0fbd26972a1142d500e3403afb07c2a748bd"
}
```

Каждая запись `bindings` содержит `logical` (точный исторический путь),
`physical` (абсолютный локальный путь к файлу), `sha256` (64 шестнадцатеричных
символа нижнего регистра) и `role`: `source`, `metadata` или `payload`.
Исходники основного runtime привязываются к сохранённым файлам клона автоматически;
остальные входы требуют явных записей. Нужны полный пакет признаков и его
метаданные, исходники и входы закреплённого исторического запроса, E2 checkpoint
с config и отдельным `latest.json`, завершённое хранилище запросов full-E1 с
квитанцией покрытия, старый банк со всеми десятью массивами, а также дескрипторы
и массивы графов выбранных дат. Файлы старого банка и графов должны лежать под
указанными корнями с исходными именами. Отсутствующие графы не строятся.

Поддерживается только точный исторический E2 и старый банк 32 768 строк.
Веса нового обучения не принимаются вместо закреплённых весов E2. Адаптер
проверяет исходные контрольные суммы, полное равенство конфигурации модели,
CUDA, NumPy 2.2.6 и Torch 2.8.0+cu126; для контроля ресурсов нужен `psutil`.
Исходный алгоритм сохраняет все старые строки и вычисляет 229 376 новых.

`output` должен быть новым каталогом вне входов и исходников. Результат —
`output/train/bank.json` и массивы; квитанции `started.json`, `completed.json`
или `failed.json` сохраняются в корне запуска. Для отмены создайте `output/STOP`.
Контроль срока, RSS 12 GiB, свободной RAM 2 GiB, диска 15 GiB и affinity 0x55
кооперативный: это не прежний жёсткий Windows Job limit, и блокирующий native-вызов
может задержать остановку. Частичные результаты не возобновляются автоматически.

Проверены небольшие тесты адаптеров и независимое ревью кода. Настоящая загрузка
всего исторического контекста, GPU-инференс и численная эквивалентность банка
этими проверками не подтверждены.
