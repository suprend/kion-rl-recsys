# Повторение RL по сохранённому кэшу

`train_rl.py` проверяет входные файлы. `execute_rl.py` составляет план запусков
и выполняет его только с явным флагом `--execute-training`. При подготовке
репозитория проверены планы и тесты; обучение этой командой не запускалось.

Нужны сохранённые артефакты с исходной структурой каталогов и оригинальный
`bank.json`. Эти данные не входят в обычный клон репозитория. Укажите свои пути:

```powershell
python -B reproduction/train_rl.py --artifact-root C:/inputs/task2-kion --bank C:/inputs/bank/bank.json --output C:/runs/rl-replay --plan-output C:/plans/rl.json
python -B -m unittest discover -s reproduction -p test_train_rl.py
```

Достаточно стандартной библиотеки Python. Каталоги `C:/runs` и `C:/plans`
должны существовать. Путь `--output` должен быть свободен и находиться вне
каталогов исходников и входных данных; команда его не создаёт. Необязательный
`--plan-output` сохраняет план в новый файл вне будущего каталога результатов,
не совпадающий с входными файлами, без перезаписи существующего.

Команда проверяет SHA256 пяти исходных модулей, девяти файлов метаданных
и свидетельства выбора beta. Для 24 файлов массивов и весов проверяются только
наличие и размер: 16 массивов кэша, три массива наград, два массива полезности
и веса голов A/B/C. Если размер указан в исходных метаданных, он сравнивается
с фактическим. Содержимое массивов и весов не проверяется и не загружается;
NumPy, PyTorch и модели не запускаются.

Исходные JSON сохраняются без изменений. Таблица соответствий связывает
сохранённые пути с файлами на текущей машине. Неизвестные пути, неоднозначные
соответствия, символьные ссылки, выход за пределы каталогов и изменённые
контрольные суммы отклоняются. План отдельно фиксирует SHA256 оригинальных
исходников и кода подготовки.

В плане закреплены две функции полезности и три seed, по 1000 обновлений от
исходной головы C, CUDA FP16, Adam, размер батча 16 и residual beta
`0.16274030138555867`. Это параметры шести будущих запусков. Совпадение KL
и результатов обучения ещё предстоит проверить.

## План обучения

После подготовки входов создайте отдельный план исполнения:

```powershell
python -B reproduction/execute_rl.py --plan C:/plans/rl.json --plan-output C:/plans/rl-execution.json
```

По умолчанию в нём шесть запусков. Для одного добавьте, например,
`--utility residual --seed 20261024`. План содержит контрольную сумму
`plan_sha256`, выбранные параметры и пути. Его создание не загружает модели.
После переноса входов или изменения кода создайте оба плана заново и проверьте
новую контрольную сумму. Для повторного запуска нужен новый каталог результатов,
даже если предыдущий запуск завершился ошибкой.

## Будущий запуск

Нужна [среда actor](ENVIRONMENTS.md) и CUDA. В следующей команде замените
`DIGEST` значением `plan_sha256`, а срок задайте в UTC с часовым поясом,
не более чем на сутки вперёд. Каталог результата берётся из первого плана.

```powershell
python -B reproduction/execute_rl.py --plan C:/plans/rl-execution.json --execute-training --inspected-plan-sha256 DIGEST --deadline-utc YYYY-MM-DDTHH:MM:SSZ --cancel-file C:/runs/STOP-RL --cap-gib 8
```

Создание файла `STOP-RL` прерывает работу при следующей проверке. Контроль
срока и памяти выполняется между операциями; уже начавшаяся операция CUDA
может завершиться позже срока. Для одновременных запусков используется общая
блокировка вне репозитория. Её путь записан в плане. После аварийного завершения
блокировку нужно проверить вручную перед повторным запуском.

До создания оптимизатора команда проверяет хеши входов и точное совпадение
исходных оценок C на всех 512 историях. При расхождении обучение не начинается.
Каждый запуск сохраняет состояния на шагах 0, 250, 500 и 1000 и протокол.
Успех подтверждается `execution.json` со статусом `completed`; частичный
каталог или `aborted.json` не означают завершение.

Команда повторяет фиксированные настройки на сохранённых входах. Она не
строит кэш из сырых данных и не выполняет оценку на 64к. Совпадение результатов
нового обучения с историческими пока не проверено. Для переноса входных файлов
предусмотрена [отдельная команда](TRANSFER_INPUTS.md).
